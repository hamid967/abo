**مصدر البناء:** GitHub Actions — التشغيل [32094007348](https://github.com/hamid967/abo/actions/runs/32094007348).

## تنزيل الحزمة وتثبيتها

افتح صفحة تشغيل البناء بحساب يملك الوصول إلى مستودع `hamid967/abo`. من قسم **Artifacts** نزّل `abu-mishal-android-release-apk`، وفك ضغط الملف ثم انقل ملف `.apk` إلى جهاز Android المختبر. افتح الملف من مدير التنزيلات، واسمح بالتثبيت من المصدر الذي استخدمته إذا طلب النظام ذلك، ثم ثبّت التطبيق.

لا تنشر رابط Artifact عاماً؛ فهو يتطلب حساب GitHub مخولاً وقد تنتهي صلاحيته وفق سياسة الاحتفاظ المحددة في سير العمل.

## ضوابط الإصدار والتوقيع

يستخدم سير العمل keystore محفوظاً فقط ضمن أسرار GitHub Actions. يجب الاحتفاظ بنسخة احتياطية مشفّرة من keystore خارج المستودع، وعدم تغيير alias أو كلمات المرور بعد نشر أي إصدار للمستخدمين؛ إذ يلزم التوقيع نفسه لتحديث التطبيق لاحقاً.

| السر في GitHub Actions | الاستخدام |
|---|---|
| `ANDROID_RELEASE_KEYSTORE_BASE64` | استعادة ملف keystore داخل بيئة البناء المؤقتة. |
| `ANDROID_RELEASE_KEYSTORE_PASSWORD` | فتح keystore أثناء البناء فقط. |
| `ANDROID_RELEASE_KEY_ALIAS` | تحديد مفتاح الإصدار. |
| `ANDROID_RELEASE_KEY_PASSWORD` | استخدام مفتاح الإصدار. |

لا تضف أيّاً من هذه القيم إلى ملفات المشروع أو المحادثات أو روابط عامة.

## قبل التوزيع العام أو المتجر

يتطلب الإصدار العام إنشاء **Android App Bundle (AAB)** موقّع، ورفع رقم الإصدار، وإكمال سياسة الخصوصية ومحتوى المتجر. كما يجب أولاً ربط FCM وAPNs في حسابات الموردين واختبار الإشعارات على أجهزة فعلية، ثم إجراء اختبار قبول ثنائي الحساب على Android وiPhone/iPad. يستمر توزيع APK الموقّع كقناة اختبار داخلية فقط إلى أن تكتمل هذه الضوابط.

**AAB المتاح حالياً:** التشغيل [32101694976](https://github.com/hamid967/abo/actions/runs/32101694976)، وArtifact اسمه `abu-mishal-android-release-aab`. نزّله من GitHub ثم ارفعه إلى مسار **Internal testing** في Google Play Console؛ لا تحتاج إلى Expo Build لهذه الخطوة.

## إقفال مؤشرات النشر في لوحة المشروع

| المؤشر الظاهر | معناه | الإجراء المطلوب من مالك الحساب |
|---|---|---|
| `Expo build quota exceeded` | حصة بناء Expo السحابية غير متاحة | تجاهل زر **Build APK** واستعمل GitHub Actions للحزم الموقعة. لا يلزم رفع خطة Expo. |
| `You have unpackaged changes` | توجد تغييرات محلية لم تُحفظ ضمن نسخة مشروع | احفظ نقطة استعادة حديثة، ثم أعد فتح لوحة النشر. |
| `Backend Service — Unpublished changes` | تغييرات الخلفية لم تُنشر بعد | افتح قسم **Backend Service** في لوحة النشر واضغط زر النشر الظاهر هناك؛ هذا ينشر الخلفية فقط ولا يبني APK. |

## إعادة بناء إصدار اختبار

من المستودع افتح تبويب **Actions**، ثم اختر **Build Android APK** واضغط **Run workflow**. اختر `release` كنوع البناء، وانتظر نجاح التشغيل، ثم نزّل Artifact الجديد. سجل رقم التشغيل وتاريخ الاختبار وأي ملاحظات قبول في مركز إصدارات الجوال داخل لوحة الإدارة.
