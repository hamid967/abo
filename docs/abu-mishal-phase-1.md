# المرحلة الأولى: تحليل مشروع «أبو مشعل»

## فهم المنتج

«أبو مشعل» منصة مستقلة لمتابعة المعاملات والمهام المرتبطة بالخدمات الحكومية في المملكة العربية السعودية. وهي لا تمثل أي جهة حكومية ولا تنفذ تكاملاً مباشراً مع أبشر أو ناجز أو غيرهما ما لم يتوافر تصريح قانوني وتقني صريح. تساعد المنصة العملاء، والمنشآت، والموظفين المكلّفين بالمتابعة على تنظيم الطلبات والمستندات والمواعيد والحالات والتواصل، مع إبقاء الإجراء المطلوب التالي واضحاً لكل مستخدم.

> **مبدأ الإصدار الأول:** تبدأ المنصة بتسجيل الطلبات، متابعة دورة المعاملة، إدارة المهام والمواعيد والمرفقات، والتنبيهات الداخلية. تُبنى الوحدات المالية المتقدمة، ومركز المعرفة القابل للنشر، والذكاء الاصطناعي، وقنوات الرسائل الخارجية على مراحل لاحقة وبضوابط منفصلة.

## خريطة النظام

| الطبقة | المسؤولية | مكونات الإصدار الأول |
|---|---|---|
| تطبيق العميل | تقديم طلب، متابعة الحالة، رفع المرفقات، مراجعة المهام والمواعيد | لوحة العميل، معالج طلب جديد، تفاصيل المعاملة، مركز التنبيهات |
| مساحة الموظف | معالجة المعاملات المسندة، طلب المستندات، إدارة المهام | قائمة المعاملات، تحديث الحالة، المهام، المواعيد، الملاحظات الداخلية |
| الإدارة | تشغيل الخدمة ومراقبة الأداء وإدارة الكيانات المرجعية | مؤشرات تشغيلية، التعيين، الجهات والخدمات، الأدوار، سجل النشاط |
| واجهة الخدمات | قواعد البيانات والتحقق من المدخلات والصلاحيات | واجهات API محمية، تحقق Zod، سجل تدقيق، سياسات وصول حسب الدور |
| التخزين | حفظ المستندات والروابط الآمنة | مرفقات مرتبطة بمعاملة مع نوع الملف والحالة وبيانات المالك |
| التنبيهات | إبلاغ المستخدم عن تغيرات الحالة والمواعيد | إشعارات داخل التطبيق وتذكيرات محلية؛ قنوات البريد والرسائل مراحل لاحقة |

## المستخدمون والصلاحيات

| الدور | نطاق الوصول في الإصدار الأول | قيود صريحة |
|---|---|---|
| زائر | استعراض الخدمات العامة، الأسئلة الشائعة، وتتبع طلب بعد التحقق | لا يرى تفاصيل العميل أو الملاحظات الداخلية |
| عميل فرد | إنشاء طلباته، رفع مرفقاته، متابعة حالاتها ومواعيدها، فتح استفسار | لا يعدّل حالة المعاملة التشغيلية ولا يرى عمليات مستخدمين آخرين |
| ممثل منشأة | إدارة طلبات المنشأة المسموح له بها ومتابعة عدة مستفيدين | لا يتجاوز حدود منشأته أو الصلاحيات الممنوحة له |
| موظف / معقّب | العمل على المعاملات المسندة، تحديث الحالة، إنشاء مهمة وطلب مستند | لا يرى معاملات موظف آخر أو بيانات منشأة خارج نطاق تعيينه |
| مشرف | توزيع المعاملات، مراقبة المتأخر، مراجعة جودة الخدمة | لا يغيّر إعدادات النظام الحساسة إلا بتفويض |
| مدير النظام | إدارة المستخدمين، الأدوار، الجهات، الخدمات، المحتوى، وسجلات التدقيق | كل إجراء حساس قابل للتدقيق ولا يمنح تلقائياً لأي مستخدم عادي |

## خريطة الصفحات

| المساحة | صفحات الأولوية | نتيجة الاستخدام |
|---|---|---|
| عامة | الرئيسية، الخدمات، الأسئلة الشائعة، تتبع الطلب، الخصوصية، إخلاء المسؤولية | تعريف المستخدم بالمنصة وبدء الطلب بوضوح |
| العميل | الرئيسية، طلب جديد، معاملاتي، تفاصيل المعاملة، مهامي، مواعيدي، مستنداتي، الإشعارات، الإعدادات | متابعة كل التزامات العميل من مكان واحد |
| الموظف | مساحة العمل، المعاملات المسندة، تفاصيل المعاملة، المهام، المواعيد، التذاكر | تنفيذ الخطوة التالية وتوثيق النتيجة |
| الإدارة | مؤشرات الأداء، قائمة المعاملات، المستخدمون والأدوار، الجهات والخدمات، سجل التدقيق | إدارة التشغيل والسياسات المرجعية |

## قاعدة البيانات الأولية

يستخدم الإصدار الأول معرّفات فريدة وعلاقات صريحة وطوابع زمنية على جميع السجلات. تُضاف حقول الحذف المنطقي وسجل تغيّر الحالة في المواضع التي تتطلب قابلية الاسترجاع والتدقيق.

| الكيان | الغرض | العلاقات الأساسية |
|---|---|---|
| `profiles` | ملف المستخدم وإعدادات اللغة والتواصل | مرتبط بمستخدم النظام ودور أو أكثر |
| `organizations` و`organization_members` | عزل بيانات المنشآت وتحديد الممثلين | منشأة ← أعضاء ← طلبات ومعاملات |
| `government_entities` و`government_services` | الجهات والخدمات كبيانات مرجعية محايدة | جهة ← خدمات ← طلبات ومعاملات |
| `service_requests` | طلب العميل الأولي | عميل/منشأة، خدمة، معاملة اختيارية، مرفقات |
| `transactions` | ملف المتابعة التشغيلي | طلب، عميل، جهة، موظف مسؤول، حالة، موعد |
| `transaction_status_history` | السجل الزمني للتغيير | معاملة، حالة سابقة/لاحقة، منفّذ، ملاحظات ظاهرة وداخلية |
| `tasks` و`appointments` | العمل المطلوب والمواعيد | معاملة، مسؤول، أولوية، تاريخ استحقاق وتنبيهات |
| `documents` | بيانات الملف والمستندات المطلوبة | معاملة أو طلب، مالك، نوع، حالة تحقق، رابط تخزين |
| `support_tickets` و`ticket_messages` | الاستفسارات والتحويل إلى موظف | عميل، معاملة، مسؤول، حالة، رسائل ومرفقات |
| `notifications` و`activity_logs` | الإشعارات داخل التطبيق وسجل النشاط | مستلم، نوع، مصدر، حالة قراءة، سياق العملية |

## نطاق الإصدار الأول MVP

| داخل الإصدار الأول | مؤجل إلى مرحلة لاحقة |
|---|---|
| حسابات مستخدمين وأدوار أساسية | التحقق الثنائي عبر مزود رسائل خارجي |
| معالج طلب جديد منظم وربط الطلب بمعاملة | الدفع الإلكتروني والفواتير الضريبية |
| حالات معاملات واضحة وسجل زمني | تصدير تقارير متقدم PDF وExcel |
| مهام ومواعيد وتذكيرات محلية | ربط تقويم Google وOutlook |
| مرفقات آمنة مع قيود نوع وحجم الملف | التحكم المتقدم بالإصدارات والعلامات المائية |
| مساحة عميل وموظف وإدارة مبسطة | مساعد ذكي متصل بقاعدة معرفة منشورة |
| تنبيهات داخل التطبيق وقواعد صلاحيات أولية | بريد ورسائل نصية وواتساب عبر مزود رسمي |

## خطة التنفيذ

| المرحلة | المخرج القابل للاختبار | معيار القبول |
|---|---|---|
| 1. الهوية والتجربة | تحويل الهوية إلى «أبو مشعل»، الواجهة العربية، والإخلاء الواضح | كل الشاشات الأساسية تفهم المنصة المستقلة وتدعم RTL |
| 2. الحسابات والصلاحيات | دخول، أدوار، وحماية مسارات البيانات | لا يستطيع مستخدم رؤية سجلات خارج نطاقه |
| 3. الطلب والمعاملة | معالج الطلب، بطاقة المعاملة، دورة الحالات والسجل الزمني | يمكن إنشاء طلب ومتابعة الإجراء التالي من البداية للنهاية |
| 4. العمل التشغيلي | مهام، مواعيد، مرفقات، وتعليقات مرئية وداخلية | يستطيع الموظف إنهاء العمل المسند دون أزرار شكلية |
| 5. الإدارة والتنبيهات | التعيين، مؤشرات تشغيلية، تنبيهات داخل التطبيق | يستطيع المشرف توزيع الطلب ورصد المتأخر |
| 6. التوسعات | تذاكر الدعم، معرفة، تقارير، مدفوعات، ومساعد ذكي | كل وحدة تربط بصلاحيات وبيانات حقيقية قبل تفعيلها |

## المخاطر والافتراضات

| المجال | القرار أو الخطر | المعالجة |
|---|---|---|
| الصفة الرسمية | قد يفهم المستخدم المنصة على أنها قناة حكومية | إخلاء مسؤولية ظاهر، أيقونات محايدة، وعدم ادعاء التكامل الحكومي |
| البيانات الحساسة | الطلبات والمرفقات قد تتضمن وثائق وهوية | الحد الأدنى من البيانات، صلاحيات دقيقة، تحقق للملفات، وسجل تدقيق |
| التكاملات الحكومية | لا يجوز افتراض واجهات مباشرة مع الجهات | لا يُربط أي نظام خارجي إلا بعد تحقق قانوني وتقني وموافقة صريحة |
| المدفوعات والرسائل | تتطلب مزودين رسميين واعتمادات منفصلة | تبقى خارج الإصدار الأول حتى اختيار المزود وتوفير الاعتمادات |
| التعقيد التشغيلي | تشمل المواصفات أكثر من 20 وحدة | البدء بالـMVP مع وحدات قابلة للتوسع، ثم إضافة الوحدات وفق أثرها التشغيلي |
| المحتوى الإرشادي | قد يتغير حسب الجهة والخدمة | لا يُنشر محتوى رسمي إلا من مصادر معتمدة مع رابط وتاريخ مراجعة |

## قرار التنفيذ التالي

سيبدأ التنفيذ بتحويل التطبيق الحالي إلى هوية «أبو مشعل» وإضافة نماذج نطاق مشتركة لطلبات الخدمة والمعاملات وحالاتها التفصيلية. ثم تُنشأ قاعدة بيانات وصلاحيات العملاء والموظفين قبل إدخال المرفقات أو التذاكر أو أي قناة خارجية.
